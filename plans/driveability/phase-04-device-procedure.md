## Reproduce the available runs

Use the isolated Phase 04 commit and a fresh worktree/cache. Run `npm ci`, `npm run verify`, and a production preview on an unused browser-safe port, for example `npm run preview -- --host 127.0.0.1 --port 4191 --strictPort`. Do not use the canonical preview/cache. Create `.zone-cache/phase-04/` before running the tools.

- `npx tsx tools/physics/qualify-physics.ts .zone-cache/phase-04/physics.json`
- `npx tsx tools/physics/qualify-source-queries.ts .zone-cache/phase-04/source-queries.json`
- `npm run zone:browser -- http://127.0.0.1:4191`
- `npm run physics:browser -- http://127.0.0.1:4191 .zone-cache/phase-04/physics-browser`

For orbit/zoom/pan frames and video, run `npm run zone:rendering -- 'http://127.0.0.1:4191/?zone=cell-976969d235a150cda1f36084fb9559d8777e9d64004ebe3228780286831eaa43' .zone-cache/phase-04/rendering`.

`CAMERA_ONLY=1 npm run driving:browser -- http://127.0.0.1:4191 <output-directory>` repeats the camera/unavailable/off-road/tab/editing subset with full-frame CDP screenshots. Recordings may crop after viewport changes; use exact-dimension stills for framing/layout evidence and keep encoded-video timing separate from measured app timing.

The extra cross-engine runner uses **Puppeteer 25.10.0**, installed in an external tools directory, without changing the app dependency/lockfile. Set `PUPPETEER_MODULE` to its absolute `lib/puppeteer/puppeteer.js` and `BROWSER_PATH` to the browser executable. Run `node tools/physics/qualify-browser.mjs chromium http://127.0.0.1:4191 <output-directory>` or replace `chromium` with `firefox`. `HEADED=1` selects a displayed browser, `FUNCTIONAL_ONLY=1` runs fresh-context startup/functional checks, `PERF_ONLY=1` runs sustained/lifecycle checks, and `LIFECYCLE_ONLY=1` repeats only lifecycle/Back restoration checks. Use a new output directory for every attempt. The final runner brings each visited page to the foreground and keeps a bounded focus-event log for interrupted lifecycle diagnostics. Do not count a hidden or paused interval as a foreground drive. Run performance browsers **sequentially**, record background workload and verify the renderer backend. The script intentionally rejects generation API requests while prepared driving continues. It stores summary percentiles, command-cycle endpoints and sampled physical poses, not just READY states.

For a focused sustained recheck, set `SUSTAINED_ZONE=trafalgar-square-london` and run the cross-engine command with a new output directory. This selects only the existing 120 s Trafalgar scenario and skips cold, functional and lifecycle passes; omit `FUNCTIONAL_ONLY`/`LIFECYCLE_ONLY`. The other three planned sustained cell IDs are supported with their original durations. A recheck is optional and must retain the original indeterminate record.

Before relying on the guard, run `node --test tools/physics/qualification-protocol.test.mjs` and, with the same external Puppeteer/browser variables, `node tools/physics/verify-qualification-protocol.mjs <output-json>`. The latter uses a miniature DOM fixture and does not qualify application performance. The [review correction](./phase-04-evidence/sustained-protocol-review.json) is authoritative over the legacy sustained pass booleans.

After the production build, `npx tsx tools/physics/browser-fixtures.ts` writes the two controlled fixtures into **dist only**. Then `node tools/physics/qualify-firefox-interactions.mjs http://127.0.0.1:4191 <output-directory>` checks Firefox camera/capture/focus/tab/generation/initialization behavior. The generation scripts use delayed JSON fetch stubs. The real server/worker/cache is tested by the offline full suite; no provider acquisition is needed.

Record operator/date, exact commit and build hashes, the five artifact SHA-256s, browser/version, OS build, device model/chip/RAM, display refresh rate, orientation, viewport/DPR, power mode, thermal state and renderer details available to the inspector. Use a representative actual iPad and desktop Mac. Retain raw observations and screen recordings with the record.

Serve the unchanged **static production build** over trusted HTTPS accessible to the iPad, or an equivalent secure local test origin. Web Crypto needs a secure context; plain LAN HTTP is not equivalent to localhost. The desktop machine's `127.0.0.1` is not the iPad's localhost. Prepared driving needs no generation service: do not expose the localhost generation worker to make this test work. Hosting that service is outside this stage. Keep API unavailable during the prepared-driving cases and record the readable service notice.

## Run and retain evidence

1. Visit every prepared cell from a fresh browser context three times, with QA off. Record navigation → usable rendered vehicle, `physicsInitializationMs`, `physicsSetupMs`, actual readiness and renderer, and whether each fixed startup budget passes. Browser cache is cold; distinguish retained OS/shader caches. Warm visits are separate evidence.
2. In **Malcolm Street, Cambridge** and **West Kinzie Street, Chicago**, begin at the recorded generic starts. Drive straight, combine steering and throttle, stop, hold brake/reverse through zero into reverse, stop, and reset. Record the motion, not only the UI speed label. Repeat the recorded off-road maneuver from the physical/browser script, ending fully on pavement without reset. A manual timing miss remains a failed/indeterminate attempt; do not count a reset as an off-road return.
3. In portrait and landscape, use two fingers for pedal + steering. Slide off a held pad, release either finger independently, cancel through browser gestures, and regain focus. Check Stop versus brake/reverse, opposite pads, long holds, capture interruption, reset while held and fresh-input rearming. No stuck throttle or automatic resume is acceptable.
4. **Physically rotate** during a two-finger hold. Show/hide Safari chrome, scroll the browser chrome, pinch/page-zoom, open the location field and virtual keyboard, dismiss it, background/foreground the app, switch tabs and lock/unlock the device. Each interruption must leave neutral paused driving with explicit Resume, no catch-up, usable controls and a visible vehicle. Recheck safe areas and browser controls at 200% zoom/large text.
5. Use the controlled camera fixture URL `?artifact=/phase03-camera.zone.json`. Reverse toward the rear wall, inspect continuous retraction and stable overhead framing, then Reset vehicle and Reset view separately. Switch to Inspect, orbit/pinch/zoom/pan, then Drive; only the active owner should move the camera. The unsafe fixture must disable Drive and preserve inspection. These fixtures are **not prepared or geographic evidence**.
6. Use hardware keyboard where available and VoiceOver with Safari. Confirm accessible names, focus order/visibility, keyboard-only Drive/Pause/Inspect/reset, readable state/vehicle-unavailable feedback, and that editing/search/IME does not drive. Check held pedals with assistive technology; document any incompatibility rather than assuming semantic buttons are sufficient. No device accessibility acceptance has been established by automated element sizing.
7. Measure 60 s each of Cambridge/Chicago and 120 s each of Lucca/Trafalgar, after 2 s settling. Use repeated short driving/turn/brake/reverse cycles and explicit reset between cycles as in the runner. Append `&qualify=1` to enable `driveability:step` and `driveability:frame` PerformanceObserver entries; drain entries into a bounded collector like the runner. Record RAF intervals, sample counts, timer precision, actual elapsed duration, reset/recovery counts and frame/step percentiles. Keep timestamped drive/reset intervals, visibility/focus changes and command endpoints/step progress. Explicitly mark each deliberate reset only after checking the preceding driving endpoint, and require driving/running/visible/focused state again after Resume. Account separately for observed drive, deliberate reset and unexpected intervals; retain the original wall-duration and command-hold protocol. Report numeric budget results separately from complete foreground-protocol acceptance. Any unexplained pause, hidden/focus-lost interval, incomplete run or evidence overflow rejects acceptance even if percentiles pass; never let the next reset clear that rejection. If old sparse data cannot establish the interval, mark it incomplete/indeterminate. A final endpoint after the duration target does not establish that an unobserved pause began after the target. Do not use asset bytes, FPS guessed from video, or desktop emulation as device timing evidence.
8. Run 20 alternating Lucca/Trafalgar load/dispose cycles, three reset/Drive/pause operations and ≥2 s active time per load. Record one canvas, body/controller/collider and stable renderer counts from `qualificationResources` after a rendered frame. Use Safari Web Inspector's available memory tooling and identify exactly what it counts. Retain memory graphs over cycles 5–20, platform warnings and any context loss. If comparable reliable heap/GC/native/WASM/GPU data is unavailable, mark that measurement unmeasured and resolve the measurement/acceptance method explicitly; do not claim a memory pass from counts alone.
9. Exercise offline generation stubs for pending/reconnect/failure/cancel/replacement, selected-zone navigation, delayed/failed lazy module loading, and unmount/reload. Keep one live scene and fresh neutral inspection after successful replacement. Retain each failure and fresh-navigation recovery.

Submit the resulting record to the parent champion for independent review. Safari/iPad interaction and performance, incomplete memory evidence, any failed fixed budget, and unresolved implementation defects keep their acceptance gates open. No later-stage implementation or geographic/legal-route claim follows automatically.

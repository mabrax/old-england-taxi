## Delivered interaction

- A loaded safe cell opens paused in **Inspecting**. **Drive** explicitly focuses the canvas, enables the existing physics session and takes chase-camera ownership. **Pause driving**, Escape, UI focus, opening the workspace, blur, page hiding, pointer interruption or orientation change clear controls and leave explicit **Resume driving**. Returning focus never resumes automatically. **Inspect** pauses and returns nearby orbit/zoom/pan; QA and the catalogue remain available there. Artifact READY remains separate from physics/vehicle readiness.
- WASD and arrows map to the unchanged Phase 02 `{ throttle, steering, brake }` contract. Each key alias and pointer ID is tracked independently. Steering and a pedal combine; opposite steering cancels; opposite pedals apply brake. **S / down** and **Brake / reverse** send negative throttle: the existing controller brakes forward movement to rest, then reverses while held. **Space / Stop** brakes without reversing. Forward input similarly brakes existing reverse motion. The 8 m/s forward, 3 m/s reverse and other Phase 02 physical settings are unchanged.
- Touch uses independent left/right and three pedal buttons, captured by pointer ID. Moving outside a button retains its control until release. Releasing one pointer preserves the others. Cancellation or unexpected lost capture clears all controls and pauses; an expected lost-capture event after release does not pause. Capture failure pauses with readable feedback. The implementation follows the browser [pointer-capture contract](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture).
- Only key events targeted at the focused canvas drive. Search, coordinates, selectors, buttons and editable UI never submit driving commands. Modifier/IME transitions pause. Repeat keydown events cannot recreate a key cleared during pause/reset; a fresh press is needed. Every explicit Drive/Resume clears pointer/key state and submits neutral before accepting fresh input. No extra event loop or held-input timer is introduced.
- **Reset vehicle / R** uses the existing revalidated start, clears/recreates vehicle state and snaps camera/interpolation, then leaves driving paused. **Reset view** (also the workspace's **Reset camera**) resets only the current camera: overview in inspection, chase framing in driving/paused. It does not reset the car. Off-road/pavement-edge feedback uses the existing road triangle index and full inflated vehicle rectangle at the UI's approximately 150 ms reporting cadence. It never clamps, teleports or changes recovery. Text explains driving back inside the amber limit and using reset if stuck/overturned. Automatic escaped/fallen/invalid recovery has separate paused feedback; an unavailable spawn disables Drive and retains inspection.

## Camera and ownership

The chase follows the rendered interpolated chassis pose. It uses planar heading rather than vehicle roll/pitch, a rear offset of 9 m and height of 5.5 m above a target 0.35 m above the chassis centre (target y at least 0.9 m). Heading and position use exponential smoothing at rate 8/s with elapsed input capped at 0.1 s. It keeps the same rear orientation in reverse; no automatic front/rear swap occurs. Camera near plane is 0.1 m while chasing.

A **0.35 m sphere** is swept from the current target against the existing static Rapier geometry, excluding the dynamic chassis. Queries include ground, building faces/roofs and simulation walls, with an additional 5 cm stop margin. Both ideal framing and the smoothed result are checked; smoothing cannot carry the camera through a newly encountered wall. The query does not step or modify physics and does not create colliders. It uses the installed Rapier 0.20.0 `World.castShape` declarations.

If the available rear view is shorter than 3.2 m, the camera uses the clear space directly above the taxi, up to 8 m above its target, with the same sphere sweep. It stays overhead until rear clearance exceeds 3.8 m, avoiding view oscillation at a tight wall. Camera reset clears this hysteresis and smoothing. Visual review found a coplanar roof-panel stripe at steep overhead contact; increasing its render-only polygon offset units to −8 removed it without changing the vehicle envelope. Focused tests hold the tight-wall pose for 240 frames to check that the camera remains overhead; they also cover ground, corners, courtyard walls, heading wrap, overturned poses, translation/reverse and reset. A controlled schema-v1 fixture with a **generic validated spawn** demonstrates real rendered retraction, reversing into the rear wall, overhead framing and reset. Test fixture coordinates exist only in `tools/physics/browser-fixtures.ts`, never in runtime city rules or prepared artifacts.

OrbitControls is disabled and never updated during driving/paused mode. Its damping is drained at the ownership handoff. Inspection restores orbit ownership; reset/error transitions retain an inspection path even when there is no remaining vehicle pose. Scene tests check exclusive updates and lifecycle cleanup. One renderer RAF still owns simulation stepping, pose synchronization and camera updates. The 60 Hz/five-step catch-up bound, late initialization guards, pagehide/bfcache handling, and body/controller/world disposal remain intact.

## Browser layout and generation

The application remains web-only. Intended targets are current stable desktop Chromium, Firefox and Safari, plus Safari in representative iPadOS iPad browsers in portrait and landscape. These are intended targets, not a supported-version certification from this run. Actual device/OS/browser versions and measured budgets must be recorded when those checks are performed.

**Locations & tools** exposes the existing scrollable workspace; opening it pauses driving. Drive closes it. On widths up to 1100 px the workspace is an overlay; the driving surface otherwise has full available width. The controls use safe-area insets, dynamic viewport height, 44 px or larger targets in checked layouts, and `touch-action: none` only on the held driving buttons. Attribution remains visible while driving as well as in inspection. No orientation lock, fullscreen requirement, disabled browser zoom or native app is introduced. Portrait and landscape layouts keep the two thumb groups apart and leave the vehicle visible. Orientation changes pause so controls can be released and found again.

Generation reports busy state during searching, submission, pending/reconnected jobs and cancellation. Pending work prevents Drive/Resume even if the workspace is closed. Failures and cancellation retain the loaded world and its frozen pose, and permit explicit resume after dismissing the notice. Success follows the existing navigation path: the old page disposes its scene and the next cell starts with one canvas, a fresh world/vehicle, zero steps and neutral paused inspection.

An offline browser regression exposed an existing race: an in-flight progress response could arrive after Cancel and restore a nonterminal job. Poll requests now carry a revision; cancellation invalidates earlier responses before making its request. The browser test deliberately returns delayed progress while cancelling and verifies cancellation stays terminal. The generation architecture, request/response format, cache layout, worker and provider behavior are unchanged. Browser generation cases use clearly identified fetch stubs with JSON headers; existing tests separately exercise the real local service/worker and prepared cache without live acquisition.
